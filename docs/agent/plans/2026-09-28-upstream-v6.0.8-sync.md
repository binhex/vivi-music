# Upstream v6.0.8 Sync Implementation Plan

**For agentic workers:** REQUIRED SUB-SKILL: Use sub-agents (recommended) to implement this plan task-by-task. Steps use
  checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the fork's own tree up to upstream v6.0.8 while keeping every local patch, doc and workflow, restore the
tree's self-consistency, and make a future tree lag visible automatically.

**Architecture:** One real merge commit (`--no-commit`, then fold in the restore of upstream's stray root file) makes
the tree exactly *upstream main + the files this repo adds*. A second, non-failing job in the existing weekly
`upstream-drift.yml` asserts that invariant (every `git diff upstream/main HEAD` entry must be an addition) and reports
any violation as a step summary, a warning annotation and a deduplicated issue. Documentation is rewritten around the
in-repo flow.

**Tech Stack:** git 2.55, GitHub Actions (`actions/checkout@v4`), `gh` CLI 2.x, Bash 5 with `set -euo pipefail`, pytest,
markdownlint, PyYAML. No Android SDK/Gradle on this host.

**Spec:** `docs/agent/specs/2026-09-28-upstream-v6.0.8-sync-design.md` (commit `2011a6fc`).

**Plan location note:** saved to `docs/agent/plans/` per this repository's `AGENTS.md` rule 7, not the skill default
`docs/plans/`.

- [ ] **Step 2: Append the `freshness` job**

Append after the last step of the `drift` job (end of file, at the same two-space indentation level as `drift:`):

```yaml
  freshness:
    name: Fork tree is current with upstream main
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - name: Check out this fork
        uses: actions/checkout@v4
        with:
          ref: ${{ inputs.fork_ref || 'main' }}

      - name: Fetch upstream main
        run: |
          set -euo pipefail
          git remote add upstream https://github.com/vivizzz007/vivi-music.git
          git fetch --no-tags --depth=1 upstream main

      - name: Compare the trees
        id: tree
        run: |
          set -euo pipefail
          upstream_sha="$(git rev-parse --short upstream/main)"
          fork_sha="$(git rev-parse --short HEAD)"
          # Every difference must be a file this repo adds. A modified or deleted upstream file means
          # the tree is no longer "upstream main + our additions" - normally because it lags upstream.
          # Trees are compared, never history, so a depth-1 fetch is enough.
          git diff --name-status --no-renames upstream/main HEAD >"${RUNNER_TEMP}/tree-diff.txt"
          offending="$(grep -cvE '^A' "${RUNNER_TEMP}/tree-diff.txt" || true)"
          {
            echo "upstream_sha=${upstream_sha}"
            echo "fork_sha=${fork_sha}"
            echo "offending=${offending}"
          } >>"${GITHUB_OUTPUT}"
          echo "Fork ${fork_sha} vs upstream ${upstream_sha}: ${offending} non-additive entries"
          grep -vE '^A' "${RUNNER_TEMP}/tree-diff.txt" | head -20 || true

      - name: Report a lagging tree
        if: steps.tree.outputs.offending != '0'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail
          forked="${{ inputs.fork_ref || 'main' }}"
          upstream_sha="${{ steps.tree.outputs.upstream_sha }}"
          offending="${{ steps.tree.outputs.offending }}"
          {
            echo "### Fork tree is behind upstream main"
            echo
            echo "\`git diff --name-status upstream/main ${forked}\` reports **${offending}** entries that are"
            echo "not files this repo adds, so the tree is no longer \`upstream main + our additions\`."
            echo
            echo "Upstream tip: \`${upstream_sha}\`. First 20 entries:"
            echo
            echo '```'
            grep -vE '^A' "${RUNNER_TEMP}/tree-diff.txt" | head -20
            echo '```'
            echo
            echo "Sync with \`git fetch upstream main && git merge --no-commit upstream/main\` - see"
            echo "\`local-patches/README.md\`."
          } >>"${GITHUB_STEP_SUMMARY}"
          echo "::warning::Fork tree (${forked}) differs from upstream main (${upstream_sha}) in ${offending} non-additive entries"
          body="The fork tree (\`${forked}\`) is no longer upstream main (\`${upstream_sha}\`) plus the files this repo adds: ${offending} non-additive entries. Run: ${GITHUB_SERVER_URL}/${GITHUB_REPOSITORY}/actions/runs/${GITHUB_RUN_ID}"
          existing="$(gh issue list --repo "${GITHUB_REPOSITORY}" --state open --search '"Fork tree is behind upstream main" in:title' --json number --jq '.[0].number // empty')"
          if [[ -n "${existing}" ]]; then
            gh issue comment "${existing}" --repo "${GITHUB_REPOSITORY}" --body "${body}"
          else
            gh issue create --repo "${GITHUB_REPOSITORY}" --title "Fork tree is behind upstream main" --body "${body}"
          fi

      - name: Note a current tree and close any open lag issue
        if: steps.tree.outputs.offending == '0'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail
          forked="${{ inputs.fork_ref || 'main' }}"
          upstream_sha="${{ steps.tree.outputs.upstream_sha }}"
          echo "Fork tree (${forked}) is upstream ${upstream_sha} plus the files this repo adds." >>"${GITHUB_STEP_SUMMARY}"
          existing="$(gh issue list --repo "${GITHUB_REPOSITORY}" --state open --search '"Fork tree is behind upstream main" in:title' --json number --jq '.[0].number // empty')"
          if [[ -n "${existing}" ]]; then
            gh issue close "${existing}" --repo "${GITHUB_REPOSITORY}" \
              --comment "Fork tree is current with upstream \`${upstream_sha}\` again."
          fi
```

### Is the tree still current?

Two commands answer it, and both must pass:

```bash
git diff --name-status --no-renames upstream/main HEAD | grep -vE '^A'   # must print nothing
local-patches/apply.sh --check                                          # must print OK for every patch
```

The first says the tree is upstream plus our additions: every difference has to be an `A`dd. The second
says the patches still apply to it. The second is the one that bites - when the tree falls behind
upstream the patches go stale against it even though they still apply to upstream itself, so a checkout
of this fork quietly stops reproducing what CI builds.

### Rebasing a patch onto new upstream

Only needed when `apply.sh --check` fails, which means upstream moved a line one of the patches depends
on. Work in a clone of upstream with the patch applied on a normal branch:

```bash
# once
git remote add fork https://github.com/binhex/vivi-music.git
git fetch origin main

# put the current patch on a branch you can rebase
git switch -c local/download-folder origin/main
git apply local-patches/01-download-folder.patch   # from this repo's checkout
git commit -am "local: save completed downloads to a user-visible folder"

# ...later, after upstream releases...
git fetch origin main
git rebase origin/main        # new files + ~32 added lines in four upstream files: normally no conflict

# publish the regenerated patch
git fetch fork main
git switch -c fork-main fork/main
git diff origin/main -- app/ > local-patches/01-download-folder.patch   # app/ only: docs stay out of the patch
git commit -am "local: rebase patch 01 onto upstream $(git rev-parse --short origin/main)"
git push fork fork-main:main
git switch local/download-folder
```

If upstream did edit one of the touched lines, `git rebase` reports the file and you resolve it there.
`upstream-drift.yml` failing is the same signal, but earlier and without needing a build.

To check by hand before pushing:

```bash

cd /tmp/vivi-check && /path/to/this/repo/local-patches/apply.sh --check
```

## Rollback

| Step | Undo |
| --- | --- |
| The whole sync | `git revert -m 1 <merge-sha>` on a new commit, then push. It restores the pre-sync tree, which re-deletes `et --hard 33c82f9`; the next freshness run will then legitimately report 1 non-additive entry. |
| The canary | `git revert <ci-sha>` (or delete the `freshness` job), then push. Close the lag issue manually if it is open. |
| The docs | `git revert <docs-sha>`, then push. |
| The remote | `git remote remove upstream` (local config only; never committed). |

No tag or release is moved by any rollback, so nothing user-installable is affected.

## Out of scope (do not do these)

- Creating a tag or GitHub release, bumping a version, or touching `v6.0.8-local.1`.
- Regenerating `local-patches/01-download-folder.patch` or `02-recommendations.patch`.
- Editing `local-patches/apply.sh`, `local-patches/tests/**`, `local-build.yml`, or any `docs/agent/specs/**` file.
- `git rebase`, `git commit --amend` on a pushed commit, or any force-push.
- Pulling upstream commits beyond `206e7ae0`.
- Installing an Android toolchain on this host: Gradle, Kotlin unit tests, Kover and lint run in CI, and for
  this change the merged `app/` tree is byte-identical to upstream v6.0.8, which run `36420571484` already
  compiled and tested green.
